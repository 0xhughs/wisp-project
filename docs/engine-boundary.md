# Hidden engine boundary — slice 01

This disposable spike demonstrates a Wisp-owned stdio client over DeepSeek Harness SDK/base at `d347e703908d0406b7a7ef80e3a0e594d86b2215`. It is a technical client with no product UI. Live Qwen3 inference, actual Harness tool dispatch and ApprovalService, and durable session records were exercised. See `../evidence/01-engine-feasibility.md` for reproducible commands and bounded findings.

## Process and lifecycle

`spike/prepare.mjs` makes an independent, detached, no-hardlinks clone of the pristine pin outside the candidate, installs the unchanged lockfile and builds upstream. `spike/run.mjs` copies covered sources, expands only the absolute adapter-path placeholder in the overlay, generates a host TypeScript config, and resolves `tsx/esm` from that clone. The SDK profile uses `@deepseek-ai/dsh-base` plus `@deepseek-ai/dsh-sdk-app`; the upstream profile template creates `patchReload: startup`. The stock JSON-RPC server row is disabled. Named `wisp-sdk` plugin exports retain loader metadata and inject `sdkAppStartup`, `loader`, `agents`, `tools`, `approval`.

The parent owns inherited anonymous stdin/stdout pipes to one detached child process group. `wisp-sdk.ts` alone owns `JsonRpcLineTransport(process.stdin, process.stdout)` and `HarnessSdkJsonRpcServer(...,{maxTokensAsSuccess:false})`. There is no network listener, reusable service endpoint or authentication token. Stdout is protocol only; stderr and raw trajectories stay in the private run root. The runtime can make outbound model requests to the explicitly authorized loopback endpoint. Full upstream build produces Web artifacts as part of its build; the spike never starts a Web server or browser. Per-case owned-group `ps`/`lsof` observations found one process, no TCP listener and no browser.

Initialization waits for loader settlement and asserts the runtime tool inventory is exactly `wisp_test_effect`. Reinitialization, an unexpected session, malformed parameters, unowned cancellation and a concurrent prompt are rejected. The server remains single-session and permits only one outstanding prompt. Every acceptance scenario uses a fresh process, home, empty working directory and unique session. `shutdown` first cancels bridge entries, delegates server disposal, flushes its matching response, then awaits root disposal and transport flush before exit 0. A shared exit task bounds competing root exits; disposal failure reports `WISP_DISPOSAL_FAILED` and nonzero exit. EOF retains SDK startup handling and SIGTERM retains the upstream signal handler. Both invoke the owned root's disposal entry, which Wisp now interposes before starting transport: close admission, cancel bridge entries and the owned agent, await `Agent.whenIdle()`, explicitly await `server.shutdown()` and transport flush, then invoke the original root disposer. This preserves session-persistence listeners until cancellation audit and turn/end are appended; server handle disposal drains the session before global teardown. The root task is shared by concurrent callers and has a 4-second failure deadline, emitting a sanitized error and exiting 1 before upstream's 5-second success-coded forced-exit timer can hide a stalled disposal.

This is a **pinned private lifecycle seam**, not an upstream supported pre-disposal API: `vendor/cordis/src/fiber.ts` defines the root's own `dispose` function and runs effect teardown concurrently. The CLI `apps/cli/src/profile-boot.ts` and SDK EOF path look up that function when they dispose. `Object.defineProperty` replaces only this process root's entry; no prototypes, upstream source or global approval behavior change. The single process/startup-only profile prevents reload ambiguity. Compatibility with another pin is conditional and requires reinspection and lifecycle tests. A plugin cleanup effect alone is too late to establish this ordering.

## Reasoning and events

`initialize {cwd,provider,model}` uses the isolated absolute cwd and approved route. `session/prompt {sessionId,contentBlocks:[{type:'text',text}]}` delegates to Harness. Its `{messageId}` is a queue receipt, never completion. The client starts reading immediately and buffers `session.event` and `session.status` frames even before request replies arrive.

A passing completed turn requires contiguous session sequence numbers, the exact receipt's `user/message` inside its preceding `turn/start`, one expected turn/message, a non-interrupted nonempty `assistant/message` for that turn, `turn/end.reason.kind: completed`, and the latest session status after that exact turn/end frame must be idle. An idle frame before the turn or before its end cannot satisfy completion, even when the complete turn events were buffered before the RPC receipt. Other sessions cannot satisfy it. Aborted, blocked, error, max-token, missing/gapped events, interrupted text, premature idle, EOF and crash cannot pass. The cancel scenario instead requires the correlated aborted turn and idle; its lack of final text is expected and is not reported as successful text generation.

After successful root disposal, the client reads only the owned session tree and decodes every concatenated zstd frame in `session.v2.jsonl.zstd` (or plain JSONL). It verifies the completed/aborted turn and each approval audit pair. EOF/SIGTERM pending cases require exactly one matching asked/decided pair with cancelled outcome, followed by the correlated aborted turn/end and post-end idle notification, with zero ledger effects after exit. It does not recursively follow profile dependencies or symlinks. These records are internal diagnostics, not a user conversation-history interface.

## Approvals

The pre-execute hook denies all tools except the isolated test tool. For that tool it validates the exact live agent, owned session and open turn, parsed immutable arguments, and the prior `tool/call` fact. `tools.guard()` additionally denies other tools. The descriptor has `sessionId`, `turn`, `callId`, `toolName`, `arguments:{operation:'append-test-record',label}`, fixed `destination:'disposable-test-ledger'`, and `actionDigest`. The digest is SHA-256 of UTF-8 canonical JSON of all descriptor fields except the digest: recursively sorted object keys, JSON string escaping, no whitespace, preserved array order. No path or command is accepted in tool arguments.

The hook returns `ask`, invoking real `ToolRuntime.serviceAsk()` → `ApprovalService.request()` → `approval/request`. The bridge accepts only its captured call and original AbortSignal, checks abort before and after attaching a listener, creates a random UUID nonce and sends `wisp.approval.requested`. Notification data contains no Agent or AbortSignal. A decision is strictly `{requestId,sessionId,callId,actionDigest,decision:'allow-once'|'deny'}` via `wisp/approval.decide`. Unknown fields, altered identity, stale nonce, expiration and replay cannot authorize an effect. `wisp.approval.closed` carries the same immutable descriptor and outcome.

A matching decision atomically settles/removes the pending request. Allow creates a one-use grant checked against the full descriptor, original signal and actual call immediately before synchronous append to the process-configured ledger. No await separates this final check/consume and write. A new call, including the same label, needs a fresh nonce. Cancel before consumption wins; cancellation after the synchronous write honestly retains the already-completed one record. Withhold, deny, expiry, missing answerer and cancel produce no effect. The real registry fixture uses a minimal agent identity carrier but real Session, ToolRuntime, ApprovalService and Wisp bridge; it is not a mocked approval implementation.

`wisp/session.cancel {sessionId}` applies only to the currently active owned session and calls the actual agent's `cancel({kind:'user'})`. Its acknowledgment means requested, not completed. Pending requests settle cancelled and grants purge; turn convergence is separately observed.

The bridge UUID `requestId` is distinct from Harness's private audit ID. `approval/request` does not expose that audit ID. Durable `approval/asked` is correlated through the tool/session and then paired with `approval/decided` by their own matching audit ID. No inferred private-ID field is exposed to clients.

## Failure bounds

| Operation | Bound and outcome |
| --- | --- |
| Initialize / startup RPC | 30 seconds; malformed configuration/import fails before readiness; unknown provider/model returns error. |
| Live turn | 120 seconds; timeout remains failure, first request real cancellation, wait up to 10 seconds for idle, then terminate during cleanup if necessary. |
| Pending decision | 30 seconds; unavailable, no effect, timer/listener removed. |
| Graceful shutdown / EOF / SIGTERM exit | 10 seconds; require root disposal, exit 0 and no owned PID/group. Shutdown also requires flushed matching RPC response. |
| Fallback cleanup | SIGTERM owned group, 5 seconds; SIGKILL if needed, another bounded join. Forced termination cannot pass clean shutdown. |
| Resource probe | 30-second metadata requests, 120-second streamed request bound; no implicit provisioning or indefinite retry. |

Error names in the transport/client include `WISP_PROTOCOL`, `WISP_EVENT_GAP`, `WISP_BUSY`, `WISP_UNOWNED_SESSION`, `WISP_INVALID_PARAMS`, `WISP_STALE_OR_MISMATCHED_DECISION`, `WISP_RPC_TIMEOUT`, `WISP_TURN_TIMEOUT`, `WISP_EOF`, `WISP_DISPOSAL_FAILED` and `WISP_ORPHAN`. Raw upstream messages are kept private; tracked evidence includes only allowlisted successful assertions. Missing files and altered route metadata fail before any Harness launch with the sanitized `LIVE_RESOURCE_UNAVAILABLE` category; the approved metadata digest remains mandatory.

## Isolation, cleanup and future attachment

All engine/dependency/cache state is under `work/wisp-01/<run-id>`, with 0700 case homes and 0600 settings/proof. The process environment is constructed from known tool PATH, isolated temp/cache and explicit DSH_HOME; ambient provider keys, proxy variables, NODE_OPTIONS and configuration are not inherited. Empty cwd and DSH_HOME contain no ambient `.env` or user files. The public `ollama` placeholder is confined to the approved route hash and loopback endpoint. The short `/tmp/wisp01-<uuid>` symlink exists only to work around macOS Unix socket path length and points at the recorded root's `tmp`; it is marker-owned and removed by cleanup.

`cleanup.mjs` rejects root/ancestor paths, symlink escapes, wrong marker pin/root/alias, and changed live process identity. It signals only the recorded owned group, verifies no remaining group, unlinks the validated alias and removes that marked run root. A three-case regression includes a real detached child and confirms deletion/exit. The expensive `builder-01` clone and private proof are deliberately retained for independent Reviewer reuse, as authorized by the coordinator. Eventual removal command: `node spike/cleanup.mjs --root ../../work/wisp-01/builder-01`. The coordinator-owned Ollama process and model directory are outside this ownership and must remain untouched.

Future Wisp will attach one durable identity and user-selected state directory to this engine boundary; body changes must preserve identity, tools, connections and memory. Speech recognition supplies text and text-to-speech consumes final text through separate replaceable adapters. Voice, memory, pet bodies, settings, credentials management and any chat-like UI are not implemented here. Plugins/MCP/skills/sub-agents require additional compatibility work and global delegated-action permissions in slice 06; this spike's one-tool approval proof is deliberately narrower.
