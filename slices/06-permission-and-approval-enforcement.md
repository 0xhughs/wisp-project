## Goal

Make Wisp own the decision to execute each admitted tool action, with clear native confirmation bound to the actual operation and a fail-closed engine gate. Sending, deleting, purchasing and privileged operations cannot execute before scoped confirmation; denial, cancellation, missing or stale decisions prevent effects. Preserve the full pinned Harness SDK/base architecture and one Wisp identity, with explicit compatibility and proof requirements for every direct, plugin, MCP, skill and delegated execution route as it becomes available.

This slice builds the permission boundary and native Permissions surface. It proves them with harmless, isolated local effects through the actual Harness. It does not deliver sending, buying, privileged computer automation or the later plugin/Connection/skill management products. An unavailable route remains blocked until its own integration proof is complete; retention of its upstream service never counts as executed proof.

## Done when

1. **Native scoped decisions.** Settings → Permissions shows the enforced policy, currently admitted capability status and honest unavailable categories. A real pending tool execution produces a Wisp-owned, keyboard-accessible confirmation showing a trusted action label, operation, exact relevant target/destination, consequential inputs and whether Wisp is acting internally on the user's behalf. It offers Allow Once, Deny and Cancel Request, with no broad grant or default affirmative action. Details are bounded plain text with usable scrolling; truncation cannot hide material scope. Closing the approval window or Escape cancels its pending request. Reopening Permissions never revives a closed grant. Multiple requests remain separately identified and bounded; switching the displayed request cannot apply one request's response to another. Unknown/unsafe/unrenderable actions show a safe unavailable state and cannot be allowed. No prompt composer, transcript or Harness UI is exposed.
2. **Authoritative pre-execution gate.** Every tool body reachable in the product composition is checked by a Wisp-owned mandatory registry guard plus an approval path based on actual immutable execution facts. All consequential and otherwise unclassified actions require a supported scoped adapter or are denied. An ordinary tool's description, presentation card, name, model assertion, skill instruction, MCP annotation or another pre-execute listener cannot authorize an effect. A malicious allow-returning listener cannot bypass the guard. Exact admitted registration identity/revision, invocation identity, argument snapshot and destination determine the decision. Changed arguments/target/registration, unknown ownership, duplicate/replayed decisions, missing call facts, expired requests or invalid frames prevent body entry. One grant permits at most one corresponding execution; a second call needs a fresh decision. No stock shell/filesystem/web/job/workflow/goal/PTC route is silently enabled.
3. **Cancellation and lifecycle.** Missing/throwing answerer, denial, cancelled request, timeout, bridge EOF/failure, app Quit, reasoning apply/restart and home/identity invalidation close all affected requests and revoke unused grants before engine teardown. Late events and decisions from old native/engine generations cannot affect a new request. Cancel propagates to the owned agent and any owned child runs and waits for quiescence or proven process exit; failure to prove release leaves Wisp unavailable. Cancellation before the effect commit yields zero effect; cancellation after a completed effect is reported honestly, never as rollback. Accepted effects are not retried automatically after lost acknowledgements or restart. Closed outcomes and upstream asked/decided audit pairs remain correlated to the true call; model-visible denial/cancellation results are safe and do not expose credentials.
4. **Actual route coverage and explicit admission map.** Prove a harmless direct action and a tool registered by a real local Cordis plugin through the product adapter, actual registry and native decision channel, including pre-effect withholding, denial, cancellation and allow-once. Prove actual in-process delegated-child creation with the pinned child policy: consequential child asks are rejected under upstream `never`, parent grants do not transfer, and parent cancellation settles owned child work. Keep that constraint visible as a compatibility limit; do not fabricate child approval forwarding. Record direct, plugin, MCP, skill, in-process spawn/fork, out-of-process subagent and nested/PTC status separately with exact seams, enabled inventory, tested effects and missing gates. Every route available in the resulting product must have real boundary evidence; a future route is explicitly unavailable until its corresponding slice supplies the required actual integration proof below. A source map or mock is not a live pass, and slice06 does not claim all release route gates passed.
5. **Permissions and credential distinction.** Permissions explains Ask for each supported action and unavailable/blocked capabilities; there is no Allow Always or blanket consent. Models remains the single owner of reasoning key add/replace/remove; Permissions may show nonsecret configured/missing status and navigate there. Possession of a key, plugin installation, skill invocation, parent approval or model selection grants no action permission. Unknown capability registration or reload invalidates admission and pending grants. No arbitrary account/credential discovery, new plaintext key store or cloud request is introduced. Permission messages, native accessibility labels, diagnostics and covered artifacts exclude keys, raw bootstraps and unfiltered provider/plugin errors.
6. **Local live proof and regression.** On the declared Mac, actual local Ollama → real Harness tool call → native prompt → response → effect ledger proves the complete path. Real native input proves Allow Once, Deny, Cancel/Escape/close, request detail navigation and stale-window handling; outcomes are checked against owned effect canaries rather than UI labels alone. Build, native assertion runner and relevant existing JS/spike regressions pass. Preserve model selection/restart, safe key transport via generated sentinels, memory/identity/draft continuity, transparent-region click-through, drag, Settings close/reopen, menu controls and Quit. Live cloud evidence remains the immutable05 record; do not claim this new adapter was cloud-tested or use any further cloud calls. Final proof maps each criterion and route status to concrete artifacts and limitations.

**Action binding and admission.** Introduce a closed Wisp capability-adapter table rather than guessing semantic permissions from strings. Each admitted entry binds the actual registered tool object/generation to its code/source origin, validated argument schema, canonical action descriptor builder, allowed execution contexts and effect/cancellation contract. MCP's pinned bridge does not carry a trustworthy semantic permission classifier. Wisp owns that classification, and unknown actions cannot become safe through metadata alone.

Descriptors bind companion/engine generation, session, turn, call and root/parent execution identity when applicable, live owning agent, request nonce, capability registration revision, full canonical argument snapshot and actual resolved target. Engine-local opaque execution tokens and signals stay local; wire IDs/digest are correlation, not bearer-wide permission. Capture exact `tool/call` facts from the current open turn; for future nested/PTC calls use the actual dispatch-start vocabulary and parent token ownership, not a fabricated top-level event. In06 native mode stays enforced and unsupported nested calls fail closed. Reject malformed/ambiguous scope; do not reconstruct authorization from prior transcripts or model prose.

Render a trusted summary plus all material nonsecret fields from this descriptor, with explicit fixed limits and fail-closed overflow handling. Secret inputs are not copied to the UI: a future credential-bearing tool must use a scoped opaque credential reference with independently proved endpoint binding. If sufficient confirmation cannot be rendered without revealing a secret, the action is unavailable. Bind grants to exact snapshots; changes require a new request. Never allow a listener or wrapper to turn a missing grant into an allow. Recheck admission/ownership/signal immediately before an admitted effect; protect against registration replacement while waiting. The tool registry alone cannot hard-kill malicious in-process plugin code, so arbitrary executable plugins are not admitted by virtue of using Cordis. This is a compatibility boundary, not an OS sandbox claim.

**Delegation and later route obligations.** Retain upstream child `approvalPolicy: never`; do not change it to ask or export a parent one-shot grant. Actual child rejection is the06 enforced path. A consequential operation suggested by a child may later be proposed anew by the parent as a new actual call requiring its own confirmation; automatic transfer is not implemented. Source-supported read-only in-process delegation can be admitted only with ownership and cancellation proof; the06 developer fixture may exercise actual spawn/fork without enabling a general user-facing delegation tool. External SDK/ACP/other-product children remain disabled until separate propagation, credential, lifecycle and process-boundary evidence exists. The stock external SDK has no wire-level prompt cancel; never assume parent guard coverage extends to a separate process.
