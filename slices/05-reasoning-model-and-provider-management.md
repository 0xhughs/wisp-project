Slice: 05 Reasoning model and provider management

## Goal

Select the same Wisp's local Ollama or optional cloud reasoning backend in Wisp Settings, retain that selection across restart, protect cloud API keys separately, and demonstrate that actual Harness requests use the selected backend while Wisp identity, durable memory and independent speech state persist.

The initial supported product routes are existing local Ollama using the pinned pi-ai OpenAI-completions adapter and cloud DeepSeek using the pinned pi-ai DeepSeek catalog. This is a declared compatibility subset, not a claim that every Harness provider/model works. No cloud account is required for local use. Cloud setup is optional; live cloud acceptance evidence is mandatory for this slice and the selected release.

## Done when

1. **Usable Wisp-owned Models surface.** Settings → Models and menu Change Model reach the same native management surface. It offers Local Ollama and DeepSeek cloud, a model choice/identifier, relevant local endpoint field, credential status and secure add/replace/remove controls for cloud. It distinguishes draft, saved selection, applying, active route, untested connection and fixed safe failure states. Cancel/revert changes leave the saved/active route and credential unchanged. Invalid input cannot be saved or launched; restart and repeated window open/close retain state without duplicate windows, menu owners or engines. Models never implies microphone or speech availability. Other unsupported provider/protocol/authentication families are explicitly outside this build's compatibility list, not misleadingly enabled.
2. **Actual local and cloud selection.** From real UI input select existing local `qwen3:8b` on authorized Ollama `127.0.0.1:11434`, apply it, and complete a correlated harmless fixed turn through native → bridge → unchanged accepted SDK → actual Harness provider → Ollama. With a separately authorized DeepSeek credential/resource, add the key through the real secure field, select a supported cloud model, apply and complete the equivalent real cloud turn. Switch back locally and complete another turn with no cloud credential required or cloud request. Evidence must identify actual selected provider/model and correlated completed turn, not only saved JSON/labels or initialization success. Use only generated nonsecret test memory/content for cloud. A local stub or initialization result is supplementary evidence, never the cloud live pass.
3. **Controlled reasoning restart and continuity.** Apply stops and reaps the old bridge/engine before starting the new configuration; late events from the old generation cannot change new state. Failed startup, failed shutdown, missing key, rejected model, unavailable local endpoint and provider failure leave an honest recoverable state, with no silent fallback or automatic repeated billable test. Retry/switch back works from Wisp. Quit during apply leaves no orphan or duplicate runtime. The same native controller, companion UUID, selected home ownership and durable memory survive reasoning changes; app restart has a new controller/internal SDK session but the same companion UUID and saved route/memory. Model switching neither saves/discards an unrelated memory draft nor alters body/voice state. Actual recall on both routes proves preserved knowledge, with assembled input/deletion oracles where sampling alone is insufficient. An internal ephemeral session is not a second companion or resumed transcript.
4. **Protected cloud key lifecycle.** The cloud key is stored in macOS Keychain using a Wisp-owned, narrowly scoped item; ordinary files contain only an opaque credential identifier and route metadata. Add/replace/read across app restart/remove work with actual Security framework storage, with missing/denied/locked-store outcomes handled safely. Key fields are secure, never prefilled from storage or revealed after save; clearing a field does not silently erase a stored key. Explicit Remove Key confirms deletion of that one local key, stops any runtime using it and leaves cloud unavailable until replaced; cancellation changes nothing. Config and credential partial failures preserve a recoverable last saved choice, never claim an unsaved key/config pair active and never delete an unrelated key. No secrets enter argument lists, product events, diagnostics, route/model metadata, snapshots, editable memory, generated YAML, crash/error artifacts or covered evidence. The selected key reaches only its intended provider request via the inspected credential seam. Local use supplies a fixed nonsecret placeholder solely for pi-ai's key requirement and never looks up a cloud key.
5. **Boundary validation and isolation.** Route/model/frame validation occurs natively and at the child boundary. The local endpoint is loopback-only HTTP on an explicit port with `/v1`; remote cloud is the fixed HTTPS DeepSeek origin from the pinned catalog. Reject embedded credentials, query/fragment, malformed host/port, non-loopback local targets, remote HTTP and user-controlled secret references/headers. No raw YAML/plugin/command injection or ambient credential discovery is introduced. Corrupt/unknown-version/replaced/symlink/hardlink config and incomplete commits fail safely without modifying outside canaries. Keep the runtime cwd/DSH_HOME/TMP/cache private and separate from Wisp home. Tests prove unrelated environment, project `.env`, home files and dummy credential sentinels are not discovered or leaked. Approval remains deny-by-default and accepted spike/profile restrictions remain byte-identical; no model change enables a tool.
6. **Reviewable evidence and regression.** Build and existing CLI assertion/JS suites pass with new meaningful route, Keychain, transaction and lifecycle tests. Real native input proves save/cancel/key removal/restart/error recovery, scrolling and keyboard accessibility. Actual local→cloud→local and app restart proof plus separate secure transport/sentinel oracles map to every criterion. Preserve04 same-home recovery, memory drafts/store ownership and accepted body/shell lifecycle behavior. Existing transparent-region input/drag, close/reopen Settings and menu Quit remain functional after model editing. All required test resources and limitations are explicit; no source-only or mocked result is presented as a live gate.
