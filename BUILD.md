## Goal

Deliver a real spoken roundtrip through the existing Wisp: explicit global shortcut or Wake → bounded microphone capture → independently configured on-device recognition → the actual pinned Harness and saved active reasoning provider (local Ollama or configured DeepSeek) → committed assistant text → independently configured system speech → audible reply. Wisp visibly distinguishes listening, processing, waiting for native approval and speaking, and supports mute, cancellation and recovery without a composer, transcript interface or second agent identity. Reuse06's permission/lifecycle boundary; speech is an input/output system, never action authority.

## Done when

1. **Explicit activation and native Voice controls.** Voice admits either attached supported reasoning provider, using Models as its only provider choice. Show the active local/cloud route before capture, including that recognized text is sent to the selected cloud provider. No automatic provider switch, cloud test, retry or fallback. A registered global shortcut works while another owned test application is focused, and the menu's Wake action reaches the same state machine. Use toggle capture: first activation starts listening; a second while listening finishes the utterance; activation while processing/speaking cancels that operation and returns idle only after release, without silently starting another recording. Ignore key-repeat. Display the shortcut and finish/cancel behavior in Voice settings; handle registration conflict with a clear unavailable shortcut and usable native Wake control. Voice settings manages recognition language/local availability and a separately selected installed speech voice/rate; label unavailable on-device input locales before activation, distinguish input language from output voice and show output language/quality and mismatch information. Preserve existing selections; fresh defaults prefer an ordinary compatible installed voice. Installed Arabic output does not imply Arabic input support or natural-sounding output; Models alone manages reasoning. The defaults use the observed supported en-US route, not an inferred user-language preference. Unsupported locales are visibly unavailable, with no network fallback. Configuration and mute survive restart without changing companion/home/memory identity.
2. **Real microphone and recognition.** Capture begins only after explicit shortcut/Wake activation and actual Wisp microphone/speech permissions. No capture on launch, settings navigation, Unmute, model Apply, speech playback or retry. The first-use UI explains microphone use and on-device-only recognition, supplies correct Info.plist usage strings and contains denied/restricted/not-determined states. Use an actual microphone input, finalize exactly one nonempty recognized utterance and submit it once. Partial, empty, failed, timed-out or cancelled recognition must not create a model turn. Remove the input tap, stop the capture engine and release the recognition task on finish, cancellation, mute, device loss or failure. Local readiness is checked before requesting capture; if recognition cannot be guaranteed on-device, do not start or silently switch to Apple's server service.
3. **Actual Harness roundtrip and safe speech output.** The bounded recognized text goes through the owned native→bridge→product adapter into an actual `session/prompt`, bound to companion/engine/voice-operation generation and a unique utterance ID. The bridge owns session selection; arbitrary session IDs, extra fields, stale generations, duplicate submissions and malformed/oversized payloads are rejected. Correlate the returned message receipt to the actual current turn and its completion/idle event. Only non-interrupted committed assistant text for that request can enter TTS. Never speak reasoning blocks, tool calls/results, raw SDK/provider errors, failed/abandoned attempts or another session's answer. Use the simplest committed-result path; live token streaming and speculative audio are not required. The selected installed system voice produces actual audible speech from that model response, with actual start/finish/cancel callbacks driving speaking state. A successful synthesis call or generated WAV alone is not proof of audible output. Recognition and synthesis have separate replaceable interfaces/configuration; switching a speech voice or supported recognition locale does not switch the reasoning model or companion.
4. **Cancellation, mute and generation safety.** Voice Mute disables both microphone activation and speech output, immediately cancels active capture/recognition/reasoning/speech and discards unsaid output; Unmute does not begin listening. Cancellation before final recognition submits zero turns; cancellation during an actual provider turn closes owned approvals and waits for the owned agent to settle; cancellation after completed reasoning stops unsaid speech without claiming rollback of any committed effect. A simultaneous normal completion/cancel remains a coherent outcome, not a stale-command engine failure. Old callbacks, utterance IDs, recognition finals, response frames, queued utterances and synthesis callbacks cannot change a newer voice operation. Model Apply, home invalidation/replacement, bridge EOF/failure, device change and app Quit cancel and release affected voice/engine work. Re-activation is refused until release is established; failed release leaves a clear unavailable state. Never automatically retry recognized requests or replay speech after lost acknowledgements/restart.
5. **Permission and product invariants.** A real recognized request can reach a harmless developer verification tool through the same actual registry/native approval path; withhold/deny/cancel yield zero effect and Allow Once yields one exact effect. Microphone permission, a voice request, recognition text, model text or spoken 'yes' is not a tool grant. This slice keeps native scoped buttons as the approval mechanism; no voice approval classifier. Pause/clear competing speech when an approval requires attention and show a trusted Wisp status without reading raw tool payloads as a model answer. Keep all06 unavailable route boundaries: normal-profile unsupported direct actions, arbitrary plugins, MCP, skills, general delegation, external children and nested/PTC stay disabled until their own proofs. Preserve one identity, transparent-region click-through, body movement, native Settings/menu behavior and readable saved memory; no chat window or transcript/composer is added.
6. **Observable real proof and recovery.** On the declared Mac, actual shortcut/Wake, microphone input, on-device recognition, real local Ollama/Harness completion and audible system TTS prove the full roundtrip. Record input-source type, language/voice identifiers, actual provider/model, call correlation, state transitions and observed timing/resource data without promising latency or universal hardware/language support. Additionally prove one explicitly activated, bounded DeepSeek spoken roundtrip under the separately recorded call allowance; connection tests alone do not prove cloud voice. Prove two successive local requests, stop before transcript, stop during actual reasoning, stop during actual speech, mute/unmute, unavailable/denied devices or permissions, no-speech finalization and fresh generation after restart. Required real hardware/audio evidence cannot be replaced by fake recognition, a typed string, direct PCM injection or a local sound file alone. Supplemental deterministic tests must label their seams honestly. Native and JS checks plus relevant06 permission, operation-status and lifecycle regressions pass. Exact final identity/evidence and no-orphan cleanup are ready for independent review.
